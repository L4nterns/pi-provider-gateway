# pi-provider-gateway

面向原生 Pi / Node.js 24 的通用兼容网关扩展。只管理 **连接、协议、模型目录与能力**；上游账号、路由、额度、负载均衡、用量面板均不在职责范围内。零第三方运行时依赖，使用 Pi 提供的原生接口。Pi 作为宿主提供 peer dependencies，不随插件捆绑或锁定版本；已验证环境见 [VALIDATION.md](VALIDATION.md)。

## 使用

从公开 GitHub 仓库在线安装，不需要 GitHub token，也不需要 pic：

```sh
pi install git:github.com/L4nterns/pi-provider-gateway
```

上述来源不带版本、tag 或提交 SHA，首次安装获取仓库默认分支的当前内容。后续更新使用原生 `pi update git:github.com/L4nterns/pi-provider-gateway`；不固定来源不代表每次启动自动更新，插件本身也不实现自更新。

开发时也可本地安装：

```sh
pi install /absolute/path/to/pi-provider-gateway
```

重启 Pi 或 `/reload`，运行 `/gateway`。

```text
/gateway                 终端菜单
/gateway add             添加服务：服务 ID → URL → Key
/gateway edit [ID]       管理连接、同步目录或协议诊断
/gateway refresh [ID]    重新读取磁盘中的模型配置与缓存，不访问上游
/gateway info [ID]       只读查看模型生效配置、协议与价格来源
/gateway model [ID]      编辑模型参数或协议，保存后自动刷新
/gateway remove [ID]     确认后删除服务、凭据和扩展缓存
/model                   Pi 原生模型选择
/thinking                Pi 原生思考档位选择
```

菜单只提供六项操作，没有「返回／退出」条目；「Esc」返回，使用 Pi 原生组件与渲染。

| 操作 | 说明 |
| --- | --- |
| 添加服务 | 创建服务，填写服务 ID、URL 和 Key |
| 管理服务 | 连接、模型目录与协议诊断 |
| 刷新配置 | 重新读取本地配置，不访问上游 |
| 查看模型 | 生效参数、来源与协议 |
| 编辑模型 | 参数、价格、能力与协议偏好 |
| 删除服务 | 删除服务及其凭据和缓存 |

首次使用时只显示「添加服务」，不注册隐式默认服务。计费与删除风险在对应操作处确认。服务 ID 必填，长度 1–64，只含字母／数字／`.`／`_`／`-`，首位为字母或数字；不得与 Pi 内置 provider 同名，持久化配置中的冲突 ID 会被拒绝加载而不是覆盖原生 provider。它是 `/model` 和原生凭据的稳定关联标识，不是可随意改名的显示名称。ID 冲突、ID 或 URL 格式错误原位重新输入，「Esc」取消，不在错误消息中回显凭据。添加验证成功后才注册；取消或目录验证失败不会留下占位服务。已有服务通过「管理服务 → 连接配置」重新认证或更换 URL / Key；同一地址下留空保留原值，更换地址须重新输入 Key。删除及付费探测默认取消。

### 管理服务

```text
管理服务
  连接配置        URL、Key 与服务协议
  同步目录        读取上游模型列表，不生成内容
  协议诊断        选择模型并确认后探测，可能计费

编辑模型
  模型参数        名称、上下文、输出、输入、思考、价格与缓存
  协议偏好        仅此服务内的当前模型；自动或手动指定
```

- **连接配置**保留稳定服务 ID 和模型协议指定。提交后读取目录验证连接并自动应用模型，不询问付费探测；服务协议可保持、恢复自动或手动指定。没有可靠协议的模型保留在目录缓存中、暂不注册，之后可单独诊断或指定模型协议。更换地址／密钥不会复用旧凭据绑定的支持证据。
- **同步目录**复用已保存的 URL／Key，不重新询问凭据，不发出生成请求。重新读取上游目录、协议声明和必要的公共能力数据，保存缓存并自动应用模型；不改连接、凭据或原生模型覆盖。合法空目录清空动态模型；缺少协议的模型保留以供后续诊断。失败／取消保留原缓存与当前模型。
- **协议诊断**直接使用当前凭据绑定的缓存目录，选择单个或全部模型，再单独确认请求数量与计费风险；不经过 URL／Key 输入，也不隐式刷新目录。没有匹配缓存时提示先同步目录。可重新验证已有协议声明的模型，结果只补充支持证据，不改服务／模型协议偏好或原生参数覆盖。未选模型的证据与诊断记录保持不变；诊断不会把目录抓取时间冒充为刚更新。

**添加服务、保存连接、同步目录和模型参数保存后均自动应用。**「刷新配置」仅重新读取本地 `models.json`、服务协议与模型缓存，不访问上游，不改凭据或缓存；适合外部编辑文件后使当前 Pi 生效。「同步目录」访问上游，「协议诊断」才发出经单独授权的生成请求。

「查看模型」是只读页面：滚动／翻页查看，按「Esc」关闭，没有提交、编辑器或外部编辑器快捷键，不写入对话或修改配置。显示当前实际生效的参数、参数来源，以及自动协议／手动指定／原生模型替换后的实际协议。

模型或工具运行时，`/gateway` 立即打开菜单，查看模型信息不必等待；修改服务、重新读取模型配置或编辑模型等操作会明确提示「未执行、未排队」，由用户在任务结束后重试，不中断现有请求，也不会在输出结束后突然弹出排队的菜单。

配置和认证在 Pi 终端内完成，不需要编辑宿主机挂载目录。密钥不作为命令参数，不写入聊天记录；添加和编辑都使用遮罩密钥输入框。Pi 1.5 的原生 `/login` 对 secret 仍使用明文 Input，并回显提交值，所以本扩展的原生 `/login` 入口只提示改用 `/gateway edit <ID>`，不会向它索取密钥。凭据仍通过 Pi 原生接口持久化到 auth.json。删除当前选中服务前须先切换模型。

## 协议自动选择

支持 OpenAI Responses、Chat Completions、Anthropic Messages、Google Generative AI。每个模型单独选协议：

1. 用户明确覆盖。
2. 服务端 `native_endpoints` / `supported_endpoint_types` / 原生 Gemini 声明。
3. 添加服务时若缺少协议声明，向导询问是否探测或手动指定。已有服务在「管理服务 → 连接配置」设置服务协议，在「管理服务 → 协议诊断」选择模型并明确同意重新探测。模型级覆盖在「编辑模型 → 协议偏好」设置，可恢复自动。
4. 多协议可用时，GPT/一般模型优先 Responses，DeepSeek 优先 Chat Completions，Claude 优先 Messages，Gemini 优先原生 Gemini；这是在 **已声明或已验证支持的协议** 内的偏好，不是凭名称猜支持。

探测必须得到协议形状正确的成功响应，不能仅凭 HTTP 200。目录读取、协议诊断与公共能力补全使用 Pi 原生加载组件，「Esc」取消。显示模型、协议和总请求进度（每模型最多四次小型生成请求，并发最多 3 个模型）。添加时只探测获准的未知模型；独立诊断子任务可验证获准缓存目录中的单个或全部模型，包括已有声明的模型。确认后复用同一份目录，不二次读取或扩大请求范围。目录／能力读取限时 60 秒，批量探测总限时 10 分钟，每个 HTTP 请求限时 15 秒。本地「刷新配置」、只读信息与编辑模型不发起网络请求。

取消会等待所有探测 worker 结束再关闭等待界面和释放命令锁，不在后台继续启动请求；已经发送的请求可能已被上游接收／计费，取消无法撤销它们。目录验证失败、取消或没有成功协议时保留已有有效配置／缓存。鉴权错误、429、503、超时一律是失败／未知，不抹掉相同地址与凭据下已有支持证据。信息页区分自动优选、模型指定、服务指定和包含 Pi 原生覆盖后的**实际使用**；自动优选不等于实际协议。

探测不会在普通聊天中发生，不实现删参数后无限重试。新出现但没有协议声明、也没有已有探测记录的模型会暂不注册，在「管理服务 → 协议诊断」中明确同意探测，或在「编辑模型 → 协议偏好」指定已知协议。

端点探测思路参考 Magpie 的 `internal/provider/detect.go` 与 `test.go`（阅读版本 `814a625a24379032030fbe8300315a7f9935e3e6`），没有复制其源码。

## 模型能力与兼容性

- 网关明确的上下文、输出上限、输入模态、reasoning 和思考档位优先。
- 缺失时使用 Pi 已安装目录的精确模型匹配，再使用 models.dev 公共目录。供应商索引与模型 ID 索引相互隔离；转售商的 `供应商/模型` ID 不会被当作原厂记录。原厂引用按显示名核对，忽略大小写与标点，不做相似度匹配：`deepseek-v4.1-flash` 对应 Pi 的 `deepseek-flash`；`deepseek-v4.1-flash-1017` 仅当原厂目录把 `deepseek-flash` 命名为同一版本时使用该记录的能力（1M 上下文、384K 输出、image、low/high/max），否则仍按未知模型处理。发请求时始终保留网关原 ID；多供应商有歧义则不武断匹配。
- 仍未知时，使用标为未验证的默认值（128K / 16K / text / 非 reasoning）；不能保证任意未知模型被完整识别。
- `max` / `xhigh` 以真实档位映射保留，不把它们静默降为 high。网关明确列出的档位之外显式设为 null。公共目录声明可切换思考时 `off` 保持可选；思考档位未知时不宣称 `off` 不支持。
- 信息页按 USD／百万 tokens 列出输入、输出、缓存读取与写入价格。公共目录价格只是参考，不是网关账单；未知的零占位明确标为「不代表免费」，用户在原生覆盖中明确设置的价格单独标注来源。
- **不整包继承官方模型 compat。** Responses 不自动启用未经验证的 `prompt_cache_options`；自定义 Chat Completions 默认使用 `system` 而非 `developer`，不发送可选 `store`。DeepSeek 使用 Pi 原生 thinking 格式及工具历史所需的 `reasoning_content`；这些传输策略不降低上下文、输出、图片、工具或 max 能力，原生用户 compat 覆盖仍优先。
- 兼容 OpenAI 并不代表兼容所有可选字段；真实工具、图片与压缩仍需验收。
- Pi 原生 `models.json` 的 `modelOverrides` 是最终用户参数覆盖层；原生 `models` upsert 可替换模型协议。信息页展示生效值与来源，不把自动元数据误说成最终值。

### 编辑模型

「编辑模型 → 模型参数」提供常用字段菜单：显示名称、上下文窗口、最大输出、输入类型、思考能力、四项价格和短／长期缓存时间。显示值区分自动与用户覆盖；数字或名称留空恢复该字段自动值。价格单位为 USD／百万 tokens，缓存时间单位为秒。修改先进入内存草稿，「保存参数」才写入并应用；Esc 放弃草稿。「恢复自动」清除本模型的全部参数覆盖，仍需保存。

「高级参数」使用原生 JSON 编辑器，支持 thinking 映射、采样、输入限制、阶梯价格和 compat 等完整可编辑字段。所有入口共用 `providers[服务ID].modelOverrides[模型ID]`、原生格式验证和并发检查，不维护第二份模型注册表。仅展示可编辑参数，不把已有 headers、凭据或 URL 放进编辑器；其他模型、provider 和非编辑字段保留。

提交前由当前 Pi 原生格式验证；整个配置无效、取消、并发文件变化均拒绝覆盖。写入使用私有临时文件、文件锁和原子替换；协作锁不限制不遵守锁的外部编辑器，仍应避免同时修改。为保留注释，参数编辑器不重写 JSONC 文件，请在外部编辑后用「刷新配置」；原生刷新仍支持 JSONC。「协议偏好」是高级设置，保存在既有 Gateway `modelProtocols`，不把 schema 不支持的 `api` 写入 `modelOverrides`；原生 `models` upsert 的优先级仍高于 Gateway 选择。参数覆盖、协议偏好和付费诊断不是同一种操作。

## 持久化与边界

位置相对于 `PI_CODING_AGENT_DIR`（默认 `~/.pi/agent`）：

| 文件 | 内容 |
|---|---|
| `gateway.json` | 非秘密服务配置、协议选择 |
| `auth.json` | Pi 自己保存的凭据；通过公开 ModelRuntime 登录接口读写 |
| `models.json` | 原生用户模型配置；「编辑模型」只改选中模型的可编辑覆盖 |
| `cache/gateway/<ID>.json` | 仅模型元数据、协议结果、端点＋密钥的 SHA-256 绑定 |
| `cache/gateway/models-dev.json` | 无凭据的公共目录缓存 |

`models.json` 是可选的用户覆盖文件；不存在时使用 Gateway 元数据与 Pi 原生合并结果，无须为启动或刷新创建空文件。明确保存模型参数时才按需写入。若以前有手工覆盖，应与自己的备份核对；默认值或目录缓存不能证明旧覆盖完整，也不会自动恢复它们。

服务目录缓存 1 小时，公共目录缓存 24 小时。有缓存启动优先恢复；保存连接或同步目录失败时保留最后有效结果。经过验证的空目录清空动态模型。缓存快照缺少必要字段（例如诊断记录数组）时按无效缓存处理，不会据此发出诊断请求。`--offline` / `PI_OFFLINE=1` 不自动联网，本地刷新与模型编辑仍可用。无缓存首次启动可读取目录，但不会未经确认发出付费协议探测。

换地址／密钥后旧缓存不匹配；请求时还会检查模型的凭据绑定，拒绝用旧模型对象发出请求。缓存不保存 API Key、请求头或来自目录的任意 URL。目录／探测请求不跟随重定向；实际聊天请求的传输策略由 Pi 原生协议实现负责。URL 不接受内嵌凭据或查询参数；非本机 HTTP 连接需要确认风险。

注册完整的 Pi 原生 Provider，复用 Pi 的协议实现、工具转换、流解析和压缩。没有请求体修改 hook；没有 node_modules 补丁。配置写入是私有权限、原子替换，并有跨进程锁与冲突检查。Gateway 的协作配置操作另按服务串行到原生凭据提交／登出完成，过期配置在更改凭据前拒绝；慢连接验证后还会重新检查原生凭据，拒绝覆盖验证期间发生的外部修改。删除确认后、原生登出前重新核对所选连接与凭据；检测到变化则保留服务、当前凭据和缓存，要求重新打开菜单。普通模型请求不持该锁。这不替代原生 auth 锁，也不保证配置、缓存与原生凭据跨文件的掉电原子事务，重要数据仍须备份。

## 开发与测试

```sh
npm ci --ignore-scripts
npm run check
npm test
```

`node scripts/live-check.ts --live [--probe]` 是显式的真实网关测试：只使用已有凭据，不打印密钥；所有新缓存／设置／会话在临时目录或内存中。通过 `GATEWAY_TEST_PROVIDER`、`GATEWAY_TEST_MODEL`、`GATEWAY_TEST_URL` 指定已有服务，默认针对当前开发环境。`--probe` 最多额外发送四次协议测试请求。此脚本不是运行时的一部分。

测试包括元数据、凭据变更、离线、原子写入、协议探测、遮罩输入、Pi 原生覆盖、压缩请求载荷以及真实 Pi CLI 加载。真实网关检查另覆盖 max、工具往返、图片和 Pi 会话压缩。

## 与 pic 解耦

本仓库是独立 Pi 包，不导入或依赖 [Pi in Container](https://github.com/L4nterns/pi-container)。pic 不保存本插件源码或在镜像中复制插件目录，只通过通用引导器调用原生 `pi install`，首次从这个公开仓库的未固定来源在线安装一次；不增加启动前自动更新策略，后续安装与更新由 Pi 原生包管理负责。插件也可以在宿主机或任何其他 Pi 环境独立使用；服务配置、认证和协议策略不属于 pic。

已有本地安装不会被本仓库或 pic 自动迁移。切换安装来源前先备份 Pi 数据，通过原生包管理检查并处理旧声明，避免同时加载本地副本与 Git 副本；不要删除或覆盖 `auth.json`、模型例外或历史。
